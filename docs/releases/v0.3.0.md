## 1. Interactive Policy & Schema Editor

[`apps/agent-gate/src/components/PolicyEditorPane.tsx`](../../apps/agent-gate/src/components/PolicyEditorPane.tsx) and [`apps/agent-gate/src/components/ExprEditor.tsx`](../../apps/agent-gate/src/components/ExprEditor.tsx) provide a structured browser editor for finite-state policy models:

- **Schema & initial-state CRUD**: Add, remove, type-switch (`boolean`, `enum`, `int`), and edit initial state values with live per-path validation feedback (`indexModelDiagnostics`, `getErrorsForPathPrefix`) and collision-free logical row IDs (`alignRowIds`, `alignLocalRowIds`).
- **Order-preserving variable renames**: `applySchemaVarRenameState` and `resolveOrderedSchemaKeys` preserve visual variable slot order and active input focus even when renaming a key to an integer-like identifier (such as `secretInContext` -> `1`), while atomically rewriting variable references across rules, updates, invariants, and goals without creating spurious `UNKNOWN_VAR` errors.
- **Strict integer draft handling**: [`StrictIntegerInput.tsx`](../../apps/agent-gate/src/components/StrictIntegerInput.tsx) lifts draft state and error state by stable logical key (`StrictIntegerInput`, `parseStrictIntegerDraft`), preserving invalid drafts (such as `2.9`, `1e2`, blank values, or out-of-range integers) with `aria-invalid="true"` across rule reordering, rule disclosures, and tab switches while blocking verification (`INVALID_INTEGER_DRAFT`) until repaired.
- **Transition rules & quick-append helpers**: Edit rule metadata, nested `BoolExpr` and `ValueExpr` ASTs (`add`, `sub`, `lit`, `var`, `eq`, `neq`, `lt`, `lte`, `gt`, `gte`, `in`, `not`, `and`, `or`), atomic multi-variable updates, invariants, declared goals, and explicit `ModelAssumption[]` entries. Type-preserving `in` set editors prevent string values like `"true"` from coercing to booleans, and `handleAppendRuleGuardClause` (`shouldPruneGuardDraftsOnAppend`) prunes unreachable non-`and` guard drafts before wrapping while preserving existing `and`-clause identities.
- **Keyboard accessibility**: Five live `role="tabpanel"` panels match all `role="tab"` triggers (`ArrowLeft`/`ArrowRight`/`Home`/`End` roving tabindex navigation), every rendered `<input>`, `<select>`, and `<textarea>` pairs bidirectionally with a visible `<label for>`, and unfocused controls maintain `>= 3:1` border contrast against surface tokens (`--color-control-border`).

## 2. Portable JSON Import & Export Hardening

[`apps/agent-gate/src/model-editor.ts`](../../apps/agent-gate/src/model-editor.ts) treats imported and exported JSON structures as untrusted inputs:

- **Raw JSON number pre-validation**: `validateRawJsonNumbers` validates RFC 8259 number tokens before `JSON.parse` is invoked inside `importModelFromJson`, rejecting decimal or scientific notation (`NON_INTEGER_JSON_NUMBER`, e.g. `1.00000000000000001`, `1.0`, `1e2`) and unsafe integers outside `[Number.MIN_SAFE_INTEGER, Number.MAX_SAFE_INTEGER]` (`UNSAFE_INTEGER_JSON_NUMBER`) prior to IEEE-754 numeric rounding loss, while routing malformed JSON syntax cleanly to `JSON_PARSE_ERROR`.
- **Structural allowlist & prototype defense**: `validateImportedModelValue` inspects `Reflect.ownKeys` and `Object.getOwnPropertyDescriptor` directly, rejecting symbol keys, accessor properties, non-standard array prototypes, sparse arrays, reserved prototype keys (`__proto__`, `constructor`, `prototype`), and unsupported fields before calling `@rulecanvas/core`'s `validateModel`, returning detached plain-data snapshots.
- **Bounded deep AST round trips & resilient export UI**: `inspectStrictPlainArray`, `readExportArrayElements`, `buildDetachedBoolExpr`, and `cloneBoolExprForExport` account AST depth at `+1` per expression level within `MAX_IMPORT_DEPTH = 64` and `MAX_IMPORT_NODES = 50_000` (supporting core-valid 32-level ASTs while blocking deep DoS payloads), and `tryExportModelJson` wraps all four UI export sites so `JSON_EXPORT_ERROR` renders cleanly with the editor remaining mounted and repairable.

## 3. Verification Workbench, Counterexample Replay & Preset Comparison

[`apps/agent-gate/src/verify-client.ts`](../../apps/agent-gate/src/verify-client.ts), [`apps/agent-gate/src/components/VerificationWorkbenchPane.tsx`](../../apps/agent-gate/src/components/VerificationWorkbenchPane.tsx), and [`apps/agent-gate/src/components/ComparisonPanel.tsx`](../../apps/agent-gate/src/components/ComparisonPanel.tsx) integrate verification execution with `@rulecanvas/ui`:

- **Non-blocking Web Worker & fallback execution**: `VerifyWorkerClient` executes `verifyModel` in a dedicated Vite module worker (`verify.worker.ts`) with monotonic run-ID tracking, automatic cancellation of superseded runs on model or bound edits, and seamless synchronous main-thread fallback when Web Workers are unavailable (`isWebWorkerSupported`).
- **Snapshot-bound verdict & assumptions scope**: Results display exact explored counts, bounds, `VERIFIED`, `VERIFIED (GOAL UNREACHABLE)` (vacuous fix warning), `VIOLATED`, `INCONCLUSIVE` (`MAX_STATES` / `MAX_DEPTH`), or `INVALID` states, explicitly marking stale results (`OUTDATED:`) after edits while keeping the verified snapshot's assumptions clearly separated from unverified edited assumptions.
- **Counterexample replay & 5-preset comparison**: Uses `@rulecanvas/ui` (`createVerdictReplaySession`, `createManualSimulationSession`, `stepReplayForward`, `stepReplayBackward`, `jumpReplayToStep`, `applyManualStep`, `resetReplaySession`) to replay 5-, 6-, and 7-step approval-laundering counterexamples, branch manually, inspect variable diffs, and compare all five presets (`broken`, `naive-patch-a`, `naive-patch-b`, `vacuous-fix`, `principled-fix`) reactively under current bounds.

## 4. Correctness Guarantees & Usage

- **Semantic parity**: Every verdict, counterexample trace, enabled transition, and manual step comes directly from `@rulecanvas/core` and `@rulecanvas/ui`, with zero duplicated transition evaluators in React components.
- **Preserved library exports**: All existing scenario models (`broken`, `naive-patch-a`, `naive-patch-b`, `principled-fix`, `vacuous-fix`) and helpers remain exported cleanly from [`apps/agent-gate/src/index.ts`](../../apps/agent-gate/src/index.ts).

## 6. Known Limitations

- **Design-time discrete-state policy modeling only**: `@rulecanvas/agent-gate` evaluates user-declared bounded finite-state models under explicit `ModelAssumption[]` declarations. It does not provide real-world security guarantees, inspect live agent hosts/configs automatically, or act as a runtime firewall, MCP interception proxy, or prompt-injection filter.
- **Bounded exploration & JSON caps**: Model checking enforces core exploration caps (`maxStates <= 100,000`, `maxDepth <= 10,000`), core AST complexity limits (`depth <= 32`, `visits <= 256`), and workbench JSON import/export limits (`MAX_IMPORT_JSON_CHARS = 512,000`, `MAX_IMPORT_DEPTH = 64`, `MAX_IMPORT_NODES = 50,000`). Larger models return structured `INCONCLUSIVE` or validation errors rather than silently approximating results.
- **Standalone screenshot assets deferred to `v1.0.0`**: Repository screenshot documentation (`README.md`) remains scheduled alongside full multi-app documentation in Milestone `v1.0.0`.
